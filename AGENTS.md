# AGENTS.md — правила веб-студии

Этот репозиторий — шаблон клиентского проекта. Правила ниже обязательны для любого агента
(Codex, Claude Code и других), который работает в проекте, созданном из шаблона.

## 1. Что делать и чего не делать

- Работай только внутри этого проекта. Не меняй глобальные настройки Codex, Claude Code и других
  инструментов, не трогай соседние проекты.
- Не создавай демонстрационные страницы, примеры и заглушки без прямого запроса.
- Не добавляй зависимость, если задачу решает платформа (HTML, CSS, нативный JS) или уже
  подключённая библиотека. Каждую новую зависимость обоснуй одной строкой в ответе.
- Перед крупной работой прочитай `PRODUCT.md` и `DESIGN.md`, если они есть: это источник правды
  о продукте, аудитории и визуальной системе.

## 2. Стандарт качества

**UI/UX.** Современный профессиональный интерфейс: ясная иерархия, одна главная задача на экран,
понятные состояния (hover, focus, active, disabled, loading, empty, error), предсказуемая навигация.

**Типографика.** Не больше двух гарнитур. Модульная шкала размеров, `clamp()` для заголовков,
длина строки 60–75 символов для текста, межстрочный 1.4–1.6 для текста и 1.05–1.2 для заголовков.
Шрифты: `font-display: swap`, подгрузка только используемых начертаний и подмножеств
(кириллица, если нужна), `preload` только для шрифта первого экрана.

**Дизайн.** Выразительный, но не перегруженный: один сильный визуальный приём на секцию, сдержанная
палитра на CSS-переменных, последовательная сетка и отступы (шкала кратна 4 или 8 px).

**Адаптивность.** Mobile-first. Проверяй ширины 360, 768, 1280 и 1440 px. Без горизонтального
скролла, зоны касания от 44×44 px, `100dvh` вместо `100vh`, безопасные зоны (`env(safe-area-inset-*)`).

**Семантический HTML.** `header`, `nav`, `main`, `section`, `article`, `footer`; один `h1`, уровни
заголовков без пропусков; кнопки — `<button>`, ссылки — `<a href>`; формы с `<label>`.

**SEO.** Уникальные `<title>` и `meta description`, `lang`, canonical, Open Graph и Twitter-карточки,
`robots.txt`, `sitemap.xml`, структурированные данные JSON-LD там, где они уместны
(Organization, LocalBusiness, Product, FAQ, BreadcrumbList), человекочитаемые URL.

**Core Web Vitals.** Цели: LCP ≤ 2.5 с, INP ≤ 200 мс, CLS ≤ 0.1 на мобильном профиле.
- Изображения: AVIF/WebP, `srcset` и `sizes`, явные `width`/`height`, `loading="lazy"` ниже
  первого экрана, `fetchpriority="high"` для LCP-изображения.
- Критический CSS в начале, остальное без блокировки рендера; JS — `defer`/`type="module"`,
  разделение кода, никаких тяжёлых скриптов на первом экране.
- Сторонние скрипты (аналитика, виджеты) — отложенно и только по согласованию.

**Анимации.** Только `transform` и `opacity`; никаких анимаций `width`, `height`, `top`, `left`,
`box-shadow` в цикле. Длительность интерфейсных переходов 150–300 мс. `will-change` — точечно
и временно. Обязательно уважай `prefers-reduced-motion`. Анимация должна иметь цель, а не украшать.

**Доступность (WCAG 2.2 AA).** Контраст текста ≥ 4.5:1 (крупного ≥ 3:1), видимый `:focus-visible`,
полная работа с клавиатуры, `alt` у содержательных изображений, ARIA только там, где не хватает
семантики, ссылка «перейти к содержимому», сообщения об ошибках форм рядом с полем.

## 3. Навыки и их зоны ответственности

Навыки установлены локально: `.agents/skills/` (Codex) и `.claude/skills/` (Claude Code).

| Навык | Зона | Когда применять |
| --- | --- | --- |
| `design-taste-frontend` (Taste Skill) | Визуальный стиль и композиция | Арт-дирекция новой страницы или секции: направление, композиция, сетка, палитра, выбор шрифтов, подбор изображений |
| `impeccable` (Impeccable) | Проектирование и аудит интерфейса | `init` (контекст продукта в `PRODUCT.md`), структура и сценарии, `critique`, `audit`, `harden`, `clarify`, `adapt`, `optimize`, `polish` |
| `animate` (Emil Kowalski) | Анимации и переходы | Любое движение: микровзаимодействия, появление, переходы между состояниями, easing и длительности |

### Правила совместного использования

1. **Один навык на шаг.** На каждом шаге работы активен только навык, которому принадлежит зона.
   Не загружай несколько навыков одновременно, если их советы могут противоречить друг другу.
2. **Стиль определяет Taste.** Для новых страниц визуальное направление выбирает
   `design-taste-frontend`. Команды Impeccable, которые меняют визуальный характер
   (`bolder`, `quieter`, `colorize`, `typeset`, `overdrive`, выбор «мира» в `new-work`/`craft`),
   не применяй поверх выбранного направления без прямой просьбы пользователя.
3. **Движение определяет Animate.** Анимации проектируй и реализуй через навык `animate`,
   а не через `/impeccable animate` или раздел motion в Taste. Замечания аудита о движении
   передавай в `animate`.
4. **Аудит определяет Impeccable.** Проверку готового интерфейса (иерархия, UX, доступность,
   крайние случаи, производительность) делай через `impeccable`. Его выводы о стиле сверяй
   с направлением Taste: если они противоречат, сохраняй направление и исправляй только реальные
   дефекты (контраст, читаемость, сломанная вёрстка).
5. **Приоритет при конфликте:** запрос пользователя → `PRODUCT.md`/`DESIGN.md` → базовые правила
   этого файла (доступность и производительность не обсуждаются) → навык-владелец зоны → остальные.
6. Если пользователь явно вызывает навык или команду (`/impeccable bolder`, `$animate`),
   выполняй её, даже если она вне обычной зоны.

### Типичный порядок работы над новой страницей

1. `impeccable init` — один раз на проект, создаёт `PRODUCT.md`.
2. `design-taste-frontend` — направление, композиция, вёрстка.
3. `animate` — движение, если оно нужно.
4. `impeccable audit` / `critique` — проверка и исправление дефектов.
5. Проверка в браузере (раздел 4).

## 4. Проверка результата в браузере

Работа не считается готовой, пока не проверена в реальном браузере:
- открыть страницу локально, проверить ширины 360, 768, 1280, 1440 px и отсутствие
  горизонтального скролла;
- консоль без ошибок, нет запросов 404;
- навигация с клавиатуры и видимый фокус;
- `prefers-reduced-motion` отключает необязательное движение;
- Lighthouse (мобильный профиль): Performance, Accessibility, Best Practices, SEO ≥ 90,
  если пользователь не согласовал иное;
- в ответе перечислить, что проверено, и что не удалось проверить.

## 5. Совместная работа Claude и Codex

Над одним сайтом могут работать оба агента. Общий журнал — `AGENT_COORDINATION.md` в корне проекта.
- Перед началом работы прочитай его: задачи в работе, вопросы и последние записи.
- Займи задачу и перечисли файлы до правок; файлы, занятые другим агентом, не трогай.
- После работы добавь запись в конец журнала: что сделано, какие файлы, что проверено, что дальше.
- Решения пользователя записывай в раздел «Решения»; они обязательны для обоих агентов.
- Секреты, доступы и персональные данные в журнал не пиши.
